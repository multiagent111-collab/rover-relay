# Local candidate and future VM preparation

Prepared October 24, 2026. No cloud account, DNS, firewall, purchase or public deployment is created by these files. This profile is a separate synthetic browser fallback with actual embedded H-MEM, deterministic sample inference and simulated execution. It never calls sponsor endpoints. It contains no private ROVER code. One application writer owns `relay_state`; do not scale replicas sharing that volume.

Build from the reviewed candidate after tests and public-source review. Set `RELAY_REVISION`, real `JUDGE_HOSTNAME` and `JUDGE_PASSWORD_HASH` in a protected external environment. Generate the password hash with the chosen Caddy version's `hash-password` command, rather than storing a plaintext invitation password. Run `docker compose -f deploy/judge-compose.yml config --quiet` before a requested deployment. Resolve and record exact image digests at deployment time; `node:24-bookworm-slim` and `caddy:2` are mutable template tags, not a deployment lockfile.

Only edge publishes ports. The invitation gate protects one shared synthetic coordinator account; it does not create separate judge identities or production tenancy. Give concurrent judges separate data directories/instances when independent state is required. Keep all operational execution simulated.

Node runs directly as the container command, with an init process and 45 seconds for SIGTERM. A clean stop drains Fastify and releases the exclusive writer lock. On SIGKILL/host failure a stale lock deliberately blocks restart. Preserve the data; prove the owning process/container is gone and no other writer mounts the same volume before moving the stale lock aside into a dated recovery record. Never delete locks automatically on startup. Restart at most one writer, then verify actual memory/history and readiness. A health URL is liveness, not proof of sponsor inference/federation.

For a consistent backup: close judge ingress, stop the application cleanly, confirm the writer is gone, archive the entire volume (SQLite, WAL/SHM if present, H-MEM checkpoints/ledger and store markers together), checksum the archive, and start exactly one writer. Test a restore into a new volume/instance on private ports before replacing an existing state directory. Keep backups access-controlled; memory can contain user-entered text. A VM snapshot alone does not establish application consistency.

The original PC Relay remains a separately preserved fallback. This profile and source do not provide ROVER enrollment, its private gateway, JADE or an independently hosted live fleet. Those deployment files stay in the private ROVER project.

For a Linux VM, embedded H-MEM uses the upstream Apache-2.0 source at the pinned revision in THIRD_PARTY_NOTICES.md. The owner's application license remains a separate decision before public source distribution. Published Nightshift editions list Windows, Mac and DGX; an ordinary Ubuntu headless Nightshift package/license is not established. Do not put a Windows installer into this image or silently replace Nightshift with direct cloud inference. See [official editions](https://github.com/Meterless/Meterless/blob/main/README.md) and [Windows requirements](https://www.meterless.ai/windows.html), checked October 24, 2026. Keep optional inference disabled until the actual licensed VM-compatible endpoint is verified.
