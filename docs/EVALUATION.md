## Repeat the evaluation

From the public Relay repository, after installing locked dependencies:

```powershell
npm.cmd ci
npm.cmd run evaluate
```

The default command does not load `.env` or call sponsors. It runs the full controlled suite, seven instrumented sample scenarios, actual isolated PostgreSQL tests, official H-MEM integrity/conformance, protected baseline inventory, the working-tree production build, and a separate clean-source locked install/build/seven-scenario run. Docker and the cached `postgres:16-alpine` image are required for PostgreSQL. The independent install uses the local npm cache with `--offline --ignore-scripts`; a missing cache is a visible failed gate, not a silent skip. The initial normal `npm ci` populates that cache. No Build checkout, HACK helper, private credentials or deployed ROVER gateway is required.

For **one bounded actual Nightshift/Zetaris planning mission**, explicitly request live calls:

```powershell
npm.cmd run evaluate -- --live --accept-routed-nemotron
```

This adds the existing public `scripts/nightshift.ts` verifier in a separate child process. It reads the configured private `.env`, temporarily selects Nightshift only in that child, creates isolated SQLite/H-MEM state, confirms a synthetic entrance there, runs one normal planning mission, and correlates its model responses with Runtime receipts. It never approves dispatch, changes actual source inventory/preferences or rewrites the running app/provider configuration. The explicit flag accepts Runtime-routed NVIDIA Nemotron family models while recording their actual names; omitting it requires an exact configured label match. There is no automatic mission retry or provider fallback.

Reports default to new uniquely named `.data/evaluations/*.json` files. `--output=examples/recorded/new-report.json` selects a new report inside the repository; existing reports/configuration and outside destinations are refused. Reports preserve failed phases and return a nonzero exit for failed/unresolved public gates or a requested live failure. Every run gets a new ID/path; never replace a failed run with a later pass. Unexpected diagnostics are reduced to safe failure codes, and subprocess stderr/assertion bodies are not copied into public reports. If a phase times out or cleanup fails, inspect the retained test-owned resources before retrying; successful cleanup is not inferred from a timeout.

## Matrix and measurement rules

`scripts/evaluation/matrix.ts` binds A01–A19 to exact test names. Missing, renamed, skipped or failed evidence cannot silently pass. A20 additionally requires a successful clean run and H-MEM check; A24 requires the protected baseline and candidate source review. Any regression failure blocks the public result even if it is outside the named matrix subset. A21–A23 remain deferred regardless of controlled HTTP gateway results.

The measured sample uses public fixture revision 1 and a stated fixed business clock. UUIDs, H-MEM store identities and ports remain random; repeatability means the assertions and constraints repeat, not identical IDs. Each case records actual logical generator/snapshot counts, wall-clock duration, receipt version/digest/evidence, model-role input memory IDs and applicable task/outbox mappings. Test stock/route/preference changes are restored in isolated state, all test tasks are terminal before cleanup, and owned directories are removed. Existing demo/live state is never reset. Real serial process restart and PostgreSQL crash cases are actual processes, with controlled model/data adapters.

The live preload records service/operation/status/count/duration only, without headers, credentials, URLs or bodies. Individual fetch durations end at response headers; `missionElapsedMs` is the normal API call's end-to-end time. Counts measure Relay-to-service HTTP attempts, not Runtime-internal provider fan-out or billable NVIDIA requests. The entire regression suite's generator total is uninstrumented and is not guessed from its test count. Mock timings are never averaged into sponsor timings. One live run is a functional check, not a statistical reliability percentage.

Current A19 automated evidence covers component/API behavior and PostgreSQL chronology. The separate browser record describes actual current interactions against disposable helper instances; it does not claim those UI actions ran inside the CLI evaluator. Prior RELAY-09 mobile/Stop waiting observations and RELAY-02 independent-source mutation/restoration evidence remain explicitly historical. This ticket repeated neither mobile resizing nor mutations of current live sources.
