## Recording procedure

1. Use the fresh sample directory in [judge quickstart](JUDGE_QUICKSTART.md). Preserve the user's current mission history and live services. Record at a readable browser size, with offline/simulated labels visible. Prefer the current built production UI. Do not show `.env`, tokens, service consoles, raw logs, browser storage, desktop notifications or private trackers.
2. Rehearse once in a disposable directory. Restore fixtures before the $30 example. If setup differs from expected $32/22 and $35/28, inspect facts and narrate the actual result. Do not edit numbers to match the script.
3. Record screen and narration with the participant's chosen recorder. Aim for 3:30, within the required 1–4 minutes. If an inference operation exceeds the allotted segment, show its existing dated report or clearly mark a time cut; never present the offline generator as hosted inference.
4. Read the actual provider/model IDs in the dated report. `meterless/auto` and the configured Lightning label alone are insufficient proof. Runtime receipt matching is not independent cryptographic NVIDIA attestation. No new sponsor request is needed merely to record this explanation.
5. Review the exported video end-to-end: duration, readable text/audio, correct mode/model/execution labels, prior/new-work disclosure, no credentials/private source, no hidden cuts that imply an unobserved result. Use a new output file and retain raw footage privately. Record actual file name, duration, capture time and checksum once available.
6. Keep participant team/track choice and any external upload/submission separate. A local file is not a submitted HackOS video. RELAY-13 performs final candidate review; this ticket stops for user testing.
